### fix(freebuff): admit on /session/admission and stop at the third-party refusal
- Freebuff moved session creation to `POST /api/v1/freebuff/session/admission` and requires a client-minted instance id on a multi-session admission. Posting to the bare session route without one is answered `400 invalid_request: Desktop purchase admission requires an instance id`, which took every model on the connection down before the run started.
- The admission now mints `cli:` + a uuid v4, sends it as `x-freebuff-instance-id`, sends the bare uuid as `x-freebuff-desktop-attempt-id` (the prefixed form is answered `invalid_attempt_id`), and carries the CLI version. Release keeps the session route, as in the 0.2.36 CLI.
- Freebuff now answers a non-official client with `403 third_party_client_warning` and records a strike against the account (five suspend it). That refusal is surfaced with the upstream's own wording and strike count instead of being passed on as a bare 403 a caller may treat as retryable; the request is not retried.
