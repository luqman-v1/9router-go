### feat(combo): skip disabled members at runtime and prune deleted models/providers

- Net-new local feature (Closes #1215; no upstream `decolua/9router` parity claimed).
- **Runtime skip for disabled models/providers** (`internal/handlers/chat/combo_availability.go`, `combo.go`): filters disabled models (`disabledModels`) and providers whose stored connections are all inactive (`ProviderActiveStatus()`) once per combo dispatch before strategy selection across `/v1/chat/completions`, `/v1/messages`, `/v1/responses`, and `fusion`, preserving saved plain-combo entries so re-enabling resumes automatically. Falls back to `fallbackCombos` or returns `503 Service Unavailable` when all members are disabled.
- **Batched DB pruning on permanent deletes** (`internal/db/combos_prune.go`, `providernodes.go`, `internal/handlers/dashboard/combos_prune.go`, `models.go`): prunes permanently deleted custom models (`HandleDeleteCustomModel`, `HandleDeleteProviderModels`) and deleted provider nodes (`DeleteProviderNode`) from plain and weighted combos via batched `UPDATE ... CASE id ... WHERE id IN (...)` statements inside a single transaction, matching strictly on exact provider/node identity without cross-provider aliasing.
