### Fixed

- **A `(level)` model suffix now applies on the Responses-native lanes.** The suffix is a request override that never enters the body, so a lane that skipped the thinking pass dropped it silently: `muse/muse-spark-1.3-contributor(high)` reached the upstream with no reasoning field at all and the model ran at its own default. The thinking pass now runs on every lane, with the target format taken from the wire the upstream speaks (`openai-responses`), and the dialect follows that wire instead of the capability: a strict Responses upstream rejects a top-level `reasoning_effort` and reads `reasoning:{effort,summary}` instead. Upstream applies the pass for every target format (`open-sse/translator/index.js:137`).
- **The mandatory-reasoning clamp now runs on the Responses-native lane.** The unified thinking pass never ran when the upstream speaks the Responses API — always the case for the `muse` provider — so a client asking for no reasoning forwarded `reasoning_effort:none` unchanged and a provider that mandates reasoning answered 400 (*"Reasoning is mandatory for this endpoint and cannot be disabled"*). The clamp now happens at the dispatch chokepoint for both the Chat dialect (`reasoning_effort`) and the Responses dialect (`reasoning.effort`), so the intent reaches the upstream as `minimal`.
- **A Claude client's `thinking:{type:"disabled"}` survives the request conversion.** `TranslateClaudeToOpenAI` handled `enabled` and `adaptive` but not `disabled`, so the disable request was dropped before the thinking pass could capture it and the client silently received the provider default. The dialect now maps to `reasoning_effort:"none"`, which the pipeline already understands.
- **The mimo-free combo lane gets the clamp.** The combo path calls `MimoFreeChat` directly, so neither the thinking pass nor the clamp ran there. The clamp now runs on that lane: an explicit disable reaches the provider unchanged, and a provider that mandates reasoning answered 400. The other client dialects (`thinking:{budget}`, `thinkingConfig`, `enable_thinking`) and the operator override still do not apply on that lane — it has no thinking pass of its own.
- **Every map-to-bytes wire boundary is deterministic.** json/v2 does not order Go map keys by default, so the same request produced different bytes on the wire. The inbound thinking marshal, the Gemini generationConfig and request, the Gemini response boundaries and the request translator now marshal with `json.Deterministic(true)`, and each seam has a repeated-call test.
- **The `providerThinking` mode is validated.** Any non-empty mode was stored and written straight into `reasoning_effort`, so a hand-edited settings blob could put an invalid effort on the wire. The allowed modes are declared once, rejected on write and dropped on read.
- **An unknown effort level never reaches a provider.** A client-supplied `reasoning_effort` was forwarded verbatim, so `reasoning_effort:ultra` became `thinkingLevel:"ultra"` and any other string became an invalid enum. Both level mappers are bounded to the known vocabularies, and a level the model does not advertise is mapped onto one it does.
- **The `cache_control` markers survive for the providers that register the quirk.** Upstream's filter takes a `preserveCacheControl` option, and the alicode family on DashScope is registered with it — dropping the markers makes those gateways answer 400. The quirk is carried from the provider registry.
- **A null CommandCode field is an absent field.** Upstream reads the request fields with nullish coalescing, so a null `max_tokens`, `temperature` or `top_p` falls back to the default instead of reaching the provider as a JSON null.
- **A budget beyond the int range is rejected.** A float64 past the int range converted to an undefined value, and a numeric model suffix overflowed `strconv.Atoi` into `MaxInt64`; both now express no intent.
- **The `providerThinking` override never puts an invalid effort on the wire.** Upstream's injection chain (`chatCore.js:117-127`) falls through to `body.reasoning_effort = mode` when the client already set `body.thinking`, which writes the literal `on`/`off` as an effort — a value no provider accepts. This port keeps the chain's precedence (the operator fills a gap the client left; a client-set `reasoning_effort` outranks the injected `thinking` block, exactly as upstream's `extractThinking` orders them) but refuses the fall-through, so `on`/`off` only ever reach the wire as the `thinking` dialect they were meant to be.

### Changed

- **The per-request cost of the thinking pass is down, and the numbers are measured** (Intel Core i5-3427U @ 1.80 GHz, 4 cores, Linux; `go test -benchmem`). Each number is reproducible from the repository: `BenchmarkGetSettings` (`internal/db`), `BenchmarkFilterToOpenAIFormatJSON` (`internal/translator`) and `BenchmarkBodyMentionsThinking` (`internal/thinking`).
  - the settings read the fast path needs (`providerThinking`) was 94.5 µs, 53 allocations and 5.6 KB per call — a point query plus a JSON parse, on every request, and the fast path paid it twice. The parsed row is now reused while the row content is unchanged (the row itself is still read on every call, so the answer is never stale), which takes the read to 47.7 µs and 18 allocations, and the per-request path reads it once instead of twice: the thinking pass pays about 48 µs per request instead of about 189 µs.
  - the thinking-key scan copied the whole body (`string(raw)`) before scanning it: 1.86 ms and 524 KB per call on a 440 KB body. It now scans the bytes: 1.47 ms, 0 allocations.
  - the OpenAI filter decoded and re-serialised every request body. A body the filter does not change is now returned byte for byte, which takes a 4 KB body from 16.8 µs and 46 allocations to 9.4 µs and 35, and a 400 KB body from 188 µs to 144 µs. The bytes the client sent are the bytes the upstream sees, which is also what the upstream has cached before.
  - the thinking pass and the inbound pass now report whether they changed the body and return the client's bytes when they did not, so a body that asks for no reasoning is no longer decoded and re-serialised on the way out and an integer above 2^53 in it survives. A body the pass does rewrite is still re-serialised canonically, which is where the json/v2 float64 limit applies — the same limit upstream's `JSON.parse` has.
- The OpenAI filter is split into focused helpers, and the model-suffix scan of the request body uses the `bytes` package instead of hand-rolled byte comparisons.
- The writer table is split per format: `applyFormat` dispatches to one writer per dialect instead of running a 200-line switch, and each writer is a small function of the same context.
- The Gemini capability lookup documents its contract: the capability rows are model patterns, the pattern table carries no provider scope, and a vendor prefix on the model id is stripped.
- Every new test module is back under the project size threshold, and the retired Z.ai transform's no-op case is asserted on the wire.

### Notes

Three findings from the review turned out not to be defects, and the behaviour was left alone: the OpenAI filter's assistant-with-`tool_calls` shortcut matches upstream (upstream returns such a message as-is), the Gemini capability lookup is provider-agnostic by design, and the model-suffix scan was already linear. The first is now pinned by a test that names the upstream reference, and the `developer`-role handling on the CommandCode path — a deliberate local divergence from upstream — is pinned as well.

### Fixed

The second review round on this branch found four defects on live paths and eight smaller ones. All are fixed here.

- **The Claude translation is deterministic again.** `TranslateClaudeToOpenAI` marshalled the translated body without `json.Deterministic(true)`, so a forced single tool — which becomes a nested `tool_choice` object — reached the upstream with its two keys in a different order from one call to the next (measured: two distinct byte sequences over 400 translations of one request). A prefix-caching upstream misses the cache it would otherwise hit. Every sibling marshal on that path already carried the flag; this one did not.
- **The wire picks the reasoning dialect, not the provider registry.** `resolveFormat` consulted the provider registry before the wire, so the nine aggregators the registry records as `openai` used the OpenAI dialect on a Responses endpoint — a top-level `reasoning_effort`, which a strict Responses upstream answers with `400 unknown parameter reasoning_effort`. That is the failure this branch exists to fix, and it did not reach those providers. The target is now consulted first.
- **A body the thinking pass does not change keeps its bytes.** The pass decoded the request body into `map[string]any` and re-serialised it whenever it ran, so the client's own bytes did not reach the upstream, the keys came back in sorted order, and an integer above 2^53 came back as the next lower number. The pass now reports whether it changed anything and the input bytes are returned when it did not — on the outbound pass and on the inbound one, where the operator override decoded every request to a configured provider.
- **The operator override is written in the client's dialect.** A `providerThinking` level was injected as a top-level `reasoning_effort`, and a Claude Messages client sends the Claude wire, which has no such field: Anthropic answers an unknown top-level field with a 400. The override is now written as the Claude dialect — a disabled thinking block, an adaptive block with an effort, or an enabled block with a budget clamped into the model's declared range.
- **A `(level)` suffix resolves on an alias or a combo name.** The suffix was parsed inside the forward path, after the model name had been resolved, so `mycombo(high)` matched neither an alias nor a combo and the request was answered with "could not resolve model". The suffix now comes off the name before it is resolved, and the intent it carries travels beside the request, because the combo path replaces the body's model field with the member it is about to call.
- **The tokenrouter dialect honours the none clamp.** A model that cannot switch reasoning off received no field at all where every other writer receives the clamped lowest effort, so the upstream default applied where the client asked for none.
- **The OpenAI filter normalises the tools without a messages key.** An absent `messages` key skipped the tool and tool_choice passes entirely, so an empty tool list — the shape the filter exists to remove — reached the upstream.
- **The fast-path scan looks for a key, not for the word.** A user message that talks about reasoning matched the thinking scan, so an ordinary conversation was decoded and re-serialised for nothing.
- **The `X-PLATFORM` header uses Node's platform spelling** (`win32`, not `windows`), matching what upstream sends.
