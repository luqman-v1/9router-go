### Security

- **PEM private key detection in guardrails** ([#1282](https://github.com/luqman-v1/9router-go/pull/1282), closes [#1280](https://github.com/luqman-v1/9router-go/issues/1280)). Added a `private_key` detector to `piiDetectors` in `internal/guardrails/detectors.go` that matches PKCS#1, PKCS#8, EC, and encrypted PEM blocks and records a `PRIVATE_KEY` finding at `SeverityHigh`. Any policy enabling the `pii` detector set now blocks or masks PEM private keys; no engine change was required because `Engine.runs("pii")` already gates the set. The body character class excludes `-`, so a match terminates at the first dash of the `END` delimiter and cannot bridge repeated `BEGIN` headers — this is the RE2-legal equivalent of OmniRoute #19954's PCRE negative-lookahead pattern, and Go's RE2 engine guarantees O(N) scanning regardless. Verified by `TestScanDetectsPEMPrivateKey` (RSA/EC/encrypted fixtures, block + mask paths) and `TestScanPEMPatternLinear` (1 MB of repeated `BEGIN` headers with no `END`, scanned in 0.20 s with zero findings).
