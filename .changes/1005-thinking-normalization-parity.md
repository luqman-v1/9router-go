### Fixed

- **Step models no longer receive a reasoning field when reasoning is disabled.** Client disable dialects (`reasoning_effort:"none"`, `thinking:{type:"disabled"}`, `reasoning:{enabled:false}`, …) were forwarded verbatim (divergence, not faithful-port parity for `reasoning.enabled`: upstream `open-sse/translator/concerns/thinkingUnified.js:62-63` at decolua/9router@a07ed95 reads `reasoning.effort` only; this repo deliberately extends extraction to strict-bool `reasoning.enabled`, false→disable, true→auto), so a provider that mandates reasoning answered 400 — surfaced as `provider=cline … "Reasoning is mandatory for this endpoint and cannot be disabled"`. The new unified pass (`internal/thinking`, a port of upstream `open-sse/translator/concerns/thinkingUnified.js`) captures intent once, strips every dialect, and the `step` writer deliberately emits nothing on disable so the upstream default applies. `xhigh`/`max` clamp to `high` on step models.
- **`(level)` model suffixes are honoured on the OpenAI path.** `model(high)`, `model(none)`, `model(8192)`, `model(auto)` are stripped from the wire model and applied as the reasoning override, matching upstream `parseSuffix` (last paren wins, unknown values still strip).
- **Z.ai dialect consolidation.** The `ForwardZai` executor rewrite is retired — it re-implemented the `zai` case and its `stripThinkingFields` would delete what the unified pass just wrote. All of its assertions (none→`enable_thinking:false` / minimal clamp, low|high|max mapping, pre-5.2 drop, dialect precedence) are ported to the unified writer.
- **Deterministic serialisation of the outgoing thinking-normalised body at both seams** (`internal/thinking.ApplyJSON` and `translator.FilterToOpenAIFormatJSON`), so the same logical request yields byte-identical wire bytes for prefix-caching upstreams. Deliberate upstream divergence: upstream `thinkingUnified.js` reads `reasoning.effort` only, while this repo also honours strict-bool `reasoning.enabled`, so empty-effort + `enabled:false` disables reasoning here where upstream expresses no intent.

### Added

- **Unified thinking normalisation at the chat dispatch choke point.** Inbound half captures intent pre-conversion (with content-type strips, the `providerThinking` operator override — `on`/`off`/level, dashboard-written — and conversation-shape normalisation); outbound half (`thinking.ApplyJSON` + `filterToOpenAIFormat`) runs last on the wire body, covering both 401-retry attempts. Non-reasoning models are stripped; intent-free bodies stay byte-identical; unreachable formats are left untouched. The full writer table (openai, openai-responses, claude-adaptive, claude-budget, gemini-level, gemini-budget, zai, qwen, kimi, deepseek, minimax, hunyuan, step, tokenrouter, commandcode, kiro) matches upstream `applyFormat`, including the `none`-on-cannot-disable clamp to `minimal`.
- **Registry `thinkingFormat` for all 13 upstream providers** (`tokenrouter`, eight `openai` aggregators, the `minimax-code` pair as `claude-adaptive`; `tokenharbor` deliberately none) plus the kiro `strip:[image,audio]` model lists.
- **Gemini level/budget parity.** `reasoning_effort:high` is now budget 24576 on gemini-2.5 (was 32000) and `thinkingLevel:high` on gemini-3, with `none`/`auto` handling and upstream output floors; Claude→OpenAI uses the upstream budget thresholds.
- **Cline client identity.** Chat, OAuth refresh/exchange, and OAuth model probes present the 9Router identity (`User-Agent: 9Router/<version>`, Go runtime platform fields, `X-CLIENT-TYPE: 9router`) instead of impersonating Cline; API-key probes send `Accept`+`Authorization` only. The platform fields are the Go runtime's own values. Isolated change — revert alone if a live Cline request rejects it.
